00 / Core prerequisite

Prepare the tenant and test users

Technical configuration

Required: disposable Entra workforce tenant; User Administrator to create users; Application Administrator or Cloud Application Administrator to manage apps; Node.js 22+, npm and PowerShell 7. Keep an emergency administrator outside lab assignments.

  1. Open Entra admin center. Use the tenant switcher to select the lab directory. Open Entra ID > Overview > Properties; record Tenant ID and primary domain.
  2. Open Entra ID > Users > All users > New user > Create new user. Enter user principal name lab-app-allowed@YOUR_LAB_DOMAIN, display name lab-app-allowed, and Account enabled: Yes. Create the user and retain its temporary password securely.
  3. Repeat for lab-app-denied@YOUR_LAB_DOMAIN / lab-app-denied. Open each user's Overview and record its Object ID.
  4. For both users, open Assigned roles and Groups. Remove any lab-created administrator assignment or app-access group membership; do not use an administrator as a test user.
  5. Sign in as each user in a separate browser profile. Complete the initial password change and any required MFA registration. Leave existing Security Defaults/Conditional Access protections enabled.
  6. Open Users > User settings; record Users can register applications. No change is required when the app administrator creates the registration.
  7. Open Enterprise apps > Consent and permissions > User consent settings; record the existing setting for cleanup. Do not change it for the core scenario.

Prerequisite only: this installs Microsoft's cmdlets, not a lab helper.

Sign in, check for duplicates, and POST each user

Enter the primary domain without @. Each password prompt is secure. Record the two returned IDs and cleanup records; complete the shared first-login/MFA steps.

$ErrorActionPreference='Stop'
$TenantId=[guid](Read-Host 'Lab tenant GUID')
$AdminId=[guid](Read-Host 'Administrator USER object GUID')
Connect-MgGraph -TenantId $TenantId -Scopes 'User.ReadWrite.All','User.Read' -ContextScope Process -NoWelcome
if ((Get-MgContext).TenantId -ne $TenantId.ToString()) { throw 'Wrong tenant.' }
$Graph='https://graph.microsoft.com/v1.0'
$me=Invoke-MgGraphRequest -Method GET -Uri "$Graph/me?`$select=id" -OutputType Hashtable
if ($me.id -ne $AdminId.ToString()) { throw 'Wrong administrator.' }
if ((Read-Host 'Type APP-ACCESS-LAB to authorize lab writes') -cne 'APP-ACCESS-LAB') { throw 'Writes not confirmed.' }
$Domain=Read-Host 'Lab primary domain (without @)'
foreach ($Name in @('lab-app-allowed','lab-app-denied')) {
    $Upn="$Name@$Domain"
    $filter=[uri]::EscapeDataString("userPrincipalName eq '$($Upn.Replace("'","''"))'")
    $existing=Invoke-MgGraphRequest -Method GET -Uri "$Graph/users?`$filter=$filter" -OutputType Hashtable
    if (@($existing.value).Count) { throw "User $Upn exists; do not adopt it." }
    $secure=Read-Host "Temporary password for $Upn" -AsSecureString
    $password=[System.Net.NetworkCredential]::new('', $secure).Password
    $body=@{accountEnabled=$true;displayName=$Name;mailNickname=$Name;userPrincipalName=$Upn;userType='Member'
        passwordProfile=@{password=$password;forceChangePasswordNextSignIn=$true}}
    $user=Invoke-MgGraphRequest -Method POST -Uri "$Graph/users" -Body ($body | ConvertTo-Json -Depth 30) -ContentType 'application/json' -OutputType Hashtable
    @{path="/users/$($user.id)";identity=@{userPrincipalName=$Upn}} | ConvertTo-Json -Compress
    [pscustomobject]@{UserId=$user.id;Upn=$user.userPrincipalName}
    $password=$null
}

03 / SAML extension

Configure the gallery SAML Toolkit

Technical configuration

  1. Open Entra ID > Enterprise apps > New application. Search for Microsoft Entra SAML Toolkit, select it, set Name to APP-ACCESS-LAB-SAML and select Create.
  2. Open the app > Properties. Set Enabled for users to sign-in: Yes and Assignment required: Yes; select Save.
  3. Open Users and groups > Add user/group. Select only lab-app-allowed and select Assign.
  4. Open Single sign-on > SAML > Basic SAML Configuration > Edit. Set Reply URL to https://samltoolkit.azurewebsites.net/SAML/Consume and Sign on URL to https://samltoolkit.azurewebsites.net/. Keep the toolkit's generated Identifier (Entity ID); save.
  5. Under Attributes & Claims, verify Unique User Identifier (Name ID) uses user.userprincipalname for this toolkit account.
  6. Under SAML Certificates, download Certificate (Raw). Under Set up, record Login URL, Microsoft Entra Identifier and Logout URL.
  7. Open the toolkit site > Register. Use the allowed user's UPN as its email and create a toolkit-only password. Sign in to that toolkit account.
  8. Open SAML Configuration > Create. Enter the three Entra values from the previous step; upload the raw certificate and select Create. Record the generated SP Initiated Login URL and ACS URL.
  9. Return to Entra > Basic SAML Configuration > Edit. Replace Reply URL with the generated ACS URL and Sign on URL with the generated SP Initiated Login URL; save.
  10. Select Test > Test sign in. Authenticate as the allowed user; confirm the toolkit receives the assertion. Repeat in the denied user's profile and confirm Entra blocks the unassigned account.
