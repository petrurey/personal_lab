Before you touch a tenant

Disposable tenant only. Directory-role policies affect every assignment of that role in the tenant, not just your test user. Conditional Access can lock users out. Use an isolated tenant and a dedicated Azure subscription or lab resource group. Never modify production Global Administrator, Privileged Role Administrator, emergency accounts, or existing policies for this exercise.

Concepts that prevent the most common mistakes

Eligible means entitled to request activation, not already authorized. Active assigned is a direct administrator assignment. Activated is a temporary active assignment resulting from eligibility. Each can have its own eligibility/assignment lifetime; a 7-day eligibility does not grant 7 days of continuous active access.

Permanent eligible is not permanent active. A maximum activation duration is distinct from an assignment-expiration maximum. Directory scope / means the tenant; Azure scope is a resource ID. Graph and ARM use different identifiers and schemas.

function Connect-LabGraph {
    param([string[]]$Scopes, [string]$ExpectedUserId)
    if (Get-MgContext) { Disconnect-MgGraph | Out-Null }
    Connect-MgGraph -TenantId $TenantId -Scopes (@('User.Read') + $Scopes) `
        -ContextScope Process -NoWelcome
    $me = Invoke-MgGraphRequest -Method GET -Uri "$Graph/me"
    if ($me.id -ne $ExpectedUserId -or (Get-MgContext).TenantId -ne $TenantId) {
        Disconnect-MgGraph | Out-Null
        throw 'Wrong account or tenant. Sign in with the required lab actor.'
    }
    Write-Host "Graph actor: $($me.userPrincipalName) / $($me.id)"
}
function Get-LabGraphItems {
    param([string]$Uri)
    while ($Uri) {
        $page = Invoke-MgGraphRequest -Method GET -Uri $Uri
        foreach ($item in $page.value) { $item }
        $Uri = $page.'@odata.nextLink'
    }
}
function Write-LabGraph {
    [CmdletBinding(SupportsShouldProcess, ConfirmImpact='High')]
    param([string]$Uri, [string]$Method = 'POST', [object]$Body)
    $json = if ($null -ne $Body) { $Body | ConvertTo-Json -Depth 40 }
    if (-not $ApplyChanges) {
        Write-Host "PREVIEW: $Method $Uri"
        if ($json) { Write-Host $json }
        return
    }
    if ($PSCmdlet.ShouldProcess($Uri, $Method)) {
        $args = @{ Method=$Method; Uri=$Uri }
        if ($json) { $args.Body=$json; $args.ContentType='application/json' }
        Invoke-MgGraphRequest @args
    }
}
function Connect-LabAzure {
    param([string]$ExpectedUserId)
    Disable-AzContextAutosave -Scope Process | Out-Null
    Connect-AzAccount -Tenant $TenantId -Subscription $SubscriptionId `
        -Scope Process | Out-Null
    $ctx = Get-AzContext
    if ($ctx.Tenant.Id -ne $TenantId -or $ctx.Subscription.Id -ne $SubscriptionId) {
        throw 'Wrong Azure tenant or subscription.'
    }
    $token = (Get-AzAccessToken -ResourceUrl 'https://management.azure.com/').Token
    if ($token -is [securestring]) {
        $token = [System.Net.NetworkCredential]::new('', $token).Password
    }
    $part = $token.Split('.')[1].Replace('-', '+').Replace('_', '/')
    $part = $part.PadRight($part.Length + ((4 - $part.Length % 4) % 4), '=')
    $claims = [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($part)) |
        ConvertFrom-Json
    if ($claims.oid -ne $ExpectedUserId -or $claims.tid -ne $TenantId) {
        throw 'Wrong Azure actor. Reconnect as the required lab user.'
    }
    $token = $null
    $claims = $null
    Write-Host "ARM actor verified: $($ctx.Account.Id)"
}
function Read-LabArm {
    param([string]$Path)
    $r = Invoke-AzRestMethod -Method GET -Path $Path
    if ($r.StatusCode -ge 400) { throw $r.Content }
    $r.Content | ConvertFrom-Json -AsHashtable
}
function Get-LabArmItems {
    param([string]$Path)
    while ($Path) {
        $page = Read-LabArm $Path
        foreach ($item in $page.value) { $item }
        $Path = $page.nextLink
        if ($Path) { $Path = ([uri]$Path).PathAndQuery }
    }
}
function Write-LabArm {
    [CmdletBinding(SupportsShouldProcess, ConfirmImpact='High')]
    param([string]$Path, [string]$Method = 'PUT', [object]$Body)
    $json = if ($null -ne $Body) { $Body | ConvertTo-Json -Depth 40 }
    if (-not $ApplyChanges) {
        Write-Host "PREVIEW: $Method $Path"
        if ($json) { Write-Host $json }
        return
    }
    if ($PSCmdlet.ShouldProcess($Path, $Method)) {
        $args = @{ Method=$Method; Path=$Path }
        if ($json) { $args.Payload=$json }
        $r = Invoke-AzRestMethod @args
        if ($r.StatusCode -ge 400) { throw $r.Content }
        if ($r.Content) { $r.Content | ConvertFrom-Json -AsHashtable }
    }
}

}

$changes = @(
    @{id='Expiration_EndUser_Assignment'
      '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyExpirationRule'
      isExpirationRequired=$true; maximumDuration='PT1H'},
    @{id='Enablement_EndUser_Assignment'
      '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyEnablementRule'
      enabledRules=@('MultiFactorAuthentication','Justification','Ticketing')},
    @{id='Expiration_Admin_Eligibility'
      '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyExpirationRule'
      isExpirationRequired=$true; maximumDuration='P7D'},
    @{id='Expiration_Admin_Assignment'
      '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyExpirationRule'
      isExpirationRequired=$true; maximumDuration='P1D'},
    @{id='Enablement_Admin_Assignment'
      '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyEnablementRule'
      enabledRules=@('MultiFactorAuthentication','Justification')}
)
foreach ($change in $changes) {
    $existing = @($rules | Where-Object id -eq $change.id)
    if ($existing.Count -ne 1) { throw "Missing rule: $($change.id)" }
    $change.target = $existing[0].target
    Write-LabGraph -Method PATCH -Uri "$ruleBase/$($change.id)" -Body $change
}
$approval = @{
    '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyApprovalRule'
    id='Approval_EndUser_Assignment'

        isApprovalRequired=$true; isApprovalRequiredForExtension=$false
        isRequestorJustificationRequired=$true; approvalMode='SingleStage'

            approvalStageTimeOutInDays=1; isApproverJustificationRequired=$true
            escalationTimeInMinutes=0; isEscalationEnabled=$false
            primaryApprovers=@(@{
                '@odata.type'='#microsoft.graph.singleUser'; userId=$ApproverId
            })
            escalationApprovers=@()
        })
    }
}
Write-LabGraph -Method PATCH -Uri "$ruleBase/Approval_EndUser_Assignment" -Body $approval

$notificationId = 'Notification_Admin_EndUser_Assignment'
$notification = @{
    '@odata.type'='#microsoft.graph.unifiedRoleManagementPolicyNotificationRule'
    id=$notificationId
    target=($rules | Where-Object id -eq $notificationId).target

    Set-Content (Join-Path $Evidence 'directory-policy-after.json') -Encoding utf8

Module 05 / elevation workflow

Request, approve, deny, cancel and deactivate

Actors: operator and approver in separate profiles | 35 minutes
Operator: PIM > My roles > Microsoft Entra roles > Eligible assignments > Reports Reader > Activate
  1. Before activation, open Entra ID > Monitoring & health > Sign-in logs and try to view another lab user's events, such as the admin's recent sign-in. Record the denied/unavailable state. Ordinary users can view their own sign-ins, so your own history is not a valid privilege test. Have the admin sign in recently to ensure a positive test event exists.
  2. Select Activate. Complete additional verification when required. Use duration 30 minutes, reason PIM-LAB: inspect test reporting, ticket system LAB, ticket number CHG-PIM-001. Submit and record the request ID. Status should become pending approval rather than immediately granting access.
  3. In the approver profile, open PIM > Approve requests > Microsoft Entra roles. Inspect the requester, scope, reason, duration, and ticket. Select the request, choose Approve, provide Approved for isolated lab, and submit.
  4. Return as operator. Refresh My roles > Active assignments. Once provisioned, refresh the report or sign out/in to obtain a fresh application session. Record successful access and activation expiry. Check the relevant notification mailbox; approval, activation, and admin notifications are different events.
  5. Under Active assignments choose Deactivate once the minimum assignment interval has elapsed. Confirm the role is no longer active. Re-test after refreshing credentials; downstream applications may cache authorization.
  6. Submit a second activation. The approver chooses Deny with a reason. Confirm the denied request did not create an active assignment.
  7. Submit a third activation, then use My requests to Cancel while it is still pending. Cancellation is not deactivation. Finally, test requesting two hours: policy should prevent/reject an activation longer than one hour. Capture the error; do not change the cap.

Post-approval deferred callback: API contract, not an interactive-user shortcut

The extension service, authenticated as its registered application, resolves the exact pending request. Directory callback: Graph v1.0 /roleManagement/directory/roleAssignmentScheduleRequests/{requestId}/updateRequest. Groups callback: Graph beta /identityGovernance/privilegedAccess/group/assignmentScheduleRequests/{requestId}/updateRequest. Azure callback: ARM {scope}/providers/Microsoft.Authorization/roleAssignmentScheduleRequests/{requestId}/updateRequest?api-version=2020-10-01. Graph accepts a string reason; ARM accepts a string collection. Keep the original evaluation ID, use a final approved/denied outcome, inspect the returned status, and verify provisioning. Repeated callbacks, retries, and endpoint failures need explicit idempotency/error handling in the hosted service.

Checkpoint: if you run an advanced track, capture both a permitted and denied operation at the exact scope. If skipped, record it as optional rather than claiming it was tested.
